# 箱女 3D 非对称恐怖游戏 — 程序开发方案 V1.2

本文档交给负责程序实现的 AI（下称“实现者”）。美术资产由另一方单独制作，接口见第 6 节。

## 0. 实现者工作守则

1. 第 2 节是已确认规则，不得修改、不得增加机制、技能或胜利条件。
2. 第 3 节是待定项。遇到待定项时：数值类做成可配置参数并填占位值；规则类停下来询问，不得自行决定。
3. 第 2 节中标注 **[默认假设]** 的条目是尚未被设计者明确确认的解释，按其实现，但要做成容易改动的形式。
4. 发现规则冲突时先指出，不得私自选择。
5. 每次只推进第 5 节中的一个阶段，完成后必须能单独测试，等待确认后再进入下一阶段。
6. 所有玩法判定在服务器执行。当前版本不考虑作弊和场外语音，不需要做反作弊。
7. 不开发：箱女额外主动技能、锁门、幻觉、假声音、偷道具、箱人技能、多次猎杀、技能树、职业、成长、商店、排位、皮肤。

## 2. 已确认规则（整合版）

### 2.1 阵营与角色

- 三种角色状态：箱女、探索者、箱人。箱人与箱女同阵营。
- 箱人被消灭后，该玩家变为观战者。
- 不提供文字聊天。

### 2.2 探索者

- 可以：移动、搜索容器、拾取和使用道具、阅读日记、交换道具、语音交流、使用弱点道具、逃生。
- 探索者有手电筒（已确认）。以下细节待定：是否占背包格、开局自带还是需要搜索、有无电量、开关是否产生声音或给箱女能量、死亡时是否随其他道具一起消失。
- **任何形式的死亡都转化为箱人**，原玩家继续控制：
  - 开箱或深搜死亡：被拉入该容器，成为箱人，位于该容器内。
  - 对藏有箱女的容器使用错误弱点道具死亡：成为箱人，位于该容器内。
  - 猎杀中被处决：成为箱人，位于最近的有效容器内。
- 死亡时携带的全部道具直接消失，不掉落、不转交。

### 2.3 容器

- 所有可搜索容器都可藏匿，不分大小种类。
- 每个容器最多存放一件物品。物品被拿走后为空。
- 允许箱女和多个箱人同时藏在同一个容器内。
- 普通搜索：持续交互，所有容器时间相同。可随时取消，取消后进度清零。完成后仅在持续交互期间保持打开，停止交互自动关闭。可重复搜索。
- 深度搜索：时间为普通搜索的两倍，有概率发现秘密出口。不保证成功，不保证给线索。每次深搜给箱女额外能量。**[默认假设]** 不限制重复次数。
- 同一容器同一时刻只允许一名探索者交互，后到者被拒绝。
- 探索者可以把手持物品放回容器。**[默认假设]** 需要先打开该容器，且容器内当前没有物品。
- 容器内有箱女或箱人时，探索者完成普通搜索或深度搜索即死亡并转化。容器内的物品保留在原容器。死亡后容器恢复关闭状态，旁观者无法直接看到内部的藏匿者。
- 探索者中途取消则不触发死亡。
- **开箱不锁定藏匿者**：容器正在被打开时，里面的箱女或箱人仍然可以转移离开。
- 箱女和箱人不能进入正在被交互或打开的容器。
- 竞态裁决：以服务器收到请求的顺序为准。开箱进度只由服务器计时，客户端进度条仅用于显示。

### 2.4 箱女

- 开局只能待在容器内，不能自由离开、追逐或在容器外攻击。
- 普通转移：在容器之间移动。**没有视线或距离方面的隐蔽条件，只受转移冷却限制**。不能进入正在被交互的容器。
- 每次转移必定产生滚动音效。箱女不能主动制造任何假声音。
- 特殊转移：当前能量达到门槛后解锁，每次使用消耗能量。具体效果待定，不得自行添加全图瞬移或连续传送。
- 箱女玩家掉线：允许重连。掉线期间箱女留在原容器，探索者打开该容器仍然死亡。

### 2.5 能量

- 两个独立数值：当前能量（可消耗）、累计能量（只增不减）。
- 四种来源：时间自动恢复；探索者的声音（真实语音与动作声音）；探索者的交互行为（开箱、深搜、解锁等）；箱女靠近探索者。
- 语音能量：按说话持续时间计算，多人各自独立并累加，隔墙时削弱。说话时长由客户端上报即可。
- 输错保险箱密码产生较大声音并给箱女能量。
- 猎杀期间暂停一切能量获取。

### 2.6 猎杀

- 累计能量达到阈值后，箱女获得发动猎杀的资格，**由箱女手动发动**，整局只有一次。
- **[默认假设]** 箱女所在容器正被打开时也可以发动猎杀。
- 猎杀中：箱女离开容器，对探索者可见，可以自由追逐和抓捕。
- **猎杀期间持续消耗当前能量，能量耗尽即猎杀结束**。提前返回容器则保留剩余能量。
- 抓捕：追逐 → 抓住 → 队友救援或处决。被抓者无法正常行动。抓捕人数不设上限。
- 救援必须使用道具，不能空手。
- 主动返回：可以提前进入附近一定范围内的有效容器，不能进入正在被交互的容器。
- 强制返回：能量耗尽时，服务器把箱女送入最近的容器，要求该容器关闭、未被交互、不在任何探索者的视野锥内。找不到时退而选择最近的关闭容器。
- 猎杀结束后：不能再次离开容器或抓捕，其余能力（藏匿、普通转移、特殊转移、开箱致死）不变。

### 2.7 箱人

- 只能藏在容器内并进行普通转移（规则与箱女的普通转移相同，同样产生滚动音效）。
- 不能离开容器、猎杀、追逐、抓捕、使用特殊转移。没有能量系统。
- 探索者打开藏有箱人的容器，效果与箱女相同。

### 2.8 弱点道具

- 三种弱点道具（参考原版）：**汽油**、**白木桩**、**生锈的锁链**。每局随机一种为箱女的真正弱点，该信息只存在于服务器。
- 注意区分：“生锈的锁链”弱点道具与秘密出口上的锁链是两种不同的东西，物品 ID 和外观都要分开。
- 可以直接对容器使用，不需要先开箱。对空容器使用仍然消耗道具。
- 对容器使用时，**同时作用于容器内所有目标**：
  - 容器内的箱人全部被消灭（任意一种弱点道具都可以）。
  - 容器内的箱女：正确弱点则箱女被击杀；错误弱点则使用者死亡并转化，箱女不受影响。
- 对猎杀状态的箱女使用：
  - 正确弱点：击杀箱女。
  - 错误弱点：道具被消耗，箱女被击退；如果箱女正抓着队友，该队友被解救。

### 2.9 日记与背包

- 日记是普通物品，占一格，必须拿在手上才能阅读，可重复阅读，阅读时可以移动和奔跑。
- 日记为碎片化线索，不直接给出答案，没有自动推理，没有独立图鉴。
- 背包为普通格子式物品栏。G 丢弃手持道具，E 拾取地面道具。所有可携带道具都可以这样交换。
- 多人同时拾取同一道具时，服务器先收到的一方成功。

### 2.10 语音

- 支持开放麦和按键说话，玩家可切换。
- 探索者之间为距离语音，隔门隔墙衰减，没有声音雷达或定位箭头。
- 箱女和箱人能听到附近探索者的语音和动作声音。猎杀阶段箱女听觉范围扩大。
- 箱女阵营语音：全图、不受距离限制、探索者听不到。箱人的语音带失真效果，在收听端加滤镜实现。
- 箱人不能与探索者对话。
- 声音传播的低成本实现：距离衰减 × 固定系数（同房间 / 隔一堵墙 / 不同楼层）。

### 2.11 探索者胜利路线

**路线打开后永久开启，所有探索者都可以使用。**

1. **击杀箱女**：用正确弱点道具击杀。所有存活探索者共同获胜，对局结束。
2. **保险箱与大门**：输入 4 位密码打开保险箱，取得大门钥匙，打开大门逃离。可以不靠线索直接猜。输错后保险箱暂时锁定。个人结算。
3. **亡骸超度**：取得 Mary 玩偶和箱女亡骸并完成超度。两者都藏在普通容器中。所有存活探索者共同获胜，对局结束。
4. **秘密出口**：深度搜索发现位置，发现后地毯掀开、出口对所有人可见。全图只有一把老虎钳，用它剪断锁链后逃离。个人结算。

### 2.12 对局结束与胜负

- 路线一或路线三达成：存活探索者全体获胜，箱女阵营失败，对局结束。
- **只要有任何一名探索者成功逃离，箱女阵营即判定失败**。此后对局继续，剩余探索者继续争取个人逃离。
- 场上没有存活且未逃离的探索者时，对局结束。若此前无人逃离，箱女阵营获胜。
- 固定时限耗尽时，对局结束。若此前无人逃离，箱女阵营获胜。仍在图内的探索者失败。
- **四条路线全部作废时，箱女阵营立即获胜**。**[默认假设]** 作废判定如下：
  - 路线一：世界上已不存在正确弱点道具。
  - 路线二：大门尚未打开，且钥匙已消失。
  - 路线三：超度尚未完成，且 Mary 玩偶或亡骸已消失。
  - 路线四：锁链尚未剪断，且老虎钳已消失。
- 同一帧内的结算顺序：先结算逃离和击杀，再结算超时。

## 4. 系统架构

原则：服务器持有完整真实状态；每个客户端只收到该角色当前应当知道的内容。箱女和箱人的藏匿位置、本局弱点、未搜索容器的内容、未发现的秘密出口位置，不放进任何对探索者同步的变量里，只通过定向消息在需要时下发。

| 模块 | 职责 | 依赖 |
|---|---|---|
| Rules Core | 纯 C# 规则判定，不引用 UnityEngine，可单元测试 | — |
| Game Config | 所有待定数值的集中配置（ScriptableObject） | — |
| Session / Lobby | 房间、连接、角色分配、掉线与重连 | — |
| Match State | 对局阶段、计时器、开局随机生成 | Session, Config |
| Visibility | 按角色过滤下发内容，角色转换时切换视图 | Match State |
| Player Controller | 第一人称移动，服务器校验 | Visibility |
| Interaction | 持续交互的开始、取消、完成；服务器计时；互斥 | Player Controller |
| Container | 容器状态、内容物、藏匿者列表、普通与深度搜索 | Interaction, Rules Core |
| Item | 物品定义、地面物品、放回容器 | Match State |
| Inventory | 背包、手持、拾取、丢弃、死亡清空 | Item |
| Hider Controller | 箱女与箱人共用：藏匿、普通转移、冷却 | Container |
| Hako Onna Controller | 特殊转移、猎杀形态移动、抓捕、回箱 | Hider, Energy, Hunt |
| Energy | 当前与累计能量、四种来源、猎杀时暂停与消耗 | Sound Events, Voice |
| Hunt State | 资格、手动发动、能量消耗、主动与强制回箱 | Energy, Container |
| Sound Events | 动作声音事件、距离与房间系数衰减 | Player, Container |
| Weakness | 本局弱点（仅服务器）、道具使用判定 | Inventory, Container |
| Diary / Clue | 线索与本局弱点、密码的对应 | Weakness, Item |
| Conversion | 死亡、转化为箱人、箱人变观战 | Visibility, Inventory |
| Escape Routes | 保险箱、大门、秘密出口、锁链、超度、路线作废检测 | Item, Container |
| Victory | 个人与阵营结算、对局结束判定 | 以上全部 |
| Voice | 距离语音、阵营频道、说话时长上报 | Energy |

依赖是单向的：Rules Core 在最底层，Victory 在最上层。Voice 通过“说话活动”接口接入 Energy，在语音完成之前用假数据代替。

## 5. 分阶段开发计划

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| 0 | Rules Core 与 Game Config：容器、藏匿、开箱、转移、弱点判定的状态机 | 单元测试覆盖：开箱完成与转移离开的先后；取消开箱；进入正被交互的容器被拒绝；同容器多目标使用弱点道具 |
| 1 | 多人连接与第一人称移动，主机模式与专用服务器模式 | 多个客户端进入同一房间并互相可见 |
| 2 | 容器交互与物品 | 持续开箱、取消清零、自动关闭、取物、放回、单人互斥 |
| 3 | 背包与 G/E 交换 | 两人互换道具；同时拾取只有一人成功 |
| 4 | 箱女藏匿、普通转移、冷却、滚动音效 | 探索者端收不到箱女位置数据；转移时能听到有方向的声音 |
| 5 | 开箱死亡与箱人转化、箱人转移 | 转化后视图、操作权限、阵营正确切换；道具清空 |
| 6 | 弱点道具与路线一 | 正确、错误、对箱人、对空容器、同容器混合五种情况 |
| 7 | 能量系统（语音来源用假数据） | 当前与累计数值独立且正确 |
| 8 | 猎杀：手动发动、能量消耗、抓捕、救援、击退、处决转化、回箱 | 每局只能发动一次；强制回箱不会卡死 |
| 9 | 路线二、三、四，计时，路线作废检测，胜负结算 | 每条路线可独立通关；首人逃离后箱女判负且对局继续 |
| 10 | 距离语音、阵营语音、语音能量 | 距离衰减、频道隔离、说话产生能量 |
| 11 | 掉线与重连 | 箱女掉线后留在原容器且开箱仍致死 |

所有阶段使用灰盒占位模型，不等待美术资产。

## 6. 与美术方的接口约定

- 单位：1 Unity 单位 = 1 米。
- 目录：程序放在 `Assets/_Game/`，美术放在 `Assets/_Art/`，互不修改对方目录。
- 玩法逻辑与表现分离：每个可交互对象的预制体由“逻辑根节点 + 可替换的表现子节点”组成，美术只替换表现子节点。
- 容器预制体需要的挂点：`InteractPoint`（交互位置）、`ItemAnchor`（物品显示位置）、`GrabAnchor`（拉入动画的起点）。
- 容器开启时序：**读条期间容器保持关闭**，开箱进度只在 UI 上显示；读条完成后程序设置 `ContainerVisual.IsOpen = true` 播放打开动画；停止交互时设为 `false` 播放关闭动画；开箱致死时调用 `PlayGrab()`。
- 容器 Animator 参数（美术以后添加时使用）：`IsOpen`（bool）、`Grab`（trigger）。
- 探索者：本地玩家只显示手臂，其他玩家显示全身。
- 声音通过事件键触发，程序只引用键名，音频文件由美术方提供。目前的键：`container_open`、`container_close`、`hider_roll`、`grab`、`safe_wrong`、`chain_cut`、`carpet_reveal`、`hunt_start`、`hunt_end`。
- 需要新增挂点、动画参数或声音键时，在本节追加，不要直接写死在代码里。
