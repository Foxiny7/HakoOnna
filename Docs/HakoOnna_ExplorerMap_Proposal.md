## 1. 现状（2026-11-23 核对代码）

- 探索者没有任何地图。唯一的地图是箱女的 3D 地图：按 `Tab` 打开，看的是美术生成的简化房子 `HouseMapProxy`。它放在真房子正下方 300 m，平时关着，只在打开地图的那台客户端上打开。
- 房子一共 24 个房间（`HouseGraph`）：
  - 一楼 15 个，包括走廊、两段縁側和两个楼梯间；
  - 二楼 8 个，其中 2 个是楼梯井；
  - 院子里还有一座土蔵。
- 两部楼梯：西边的裏階段和东边的階段。从屋里能走到院子的只有玄関的大门和台所的后门；院子南边围墙上的冠木門就是路线二的大门（V1.3 9.1）。探索者在玄関出生。
- 探索者现在没有用到 `Tab`、`Z`、`X`、`C` 和鼠标右键。

## 2. 必须守住的已确认规则

| 已确认规则（出处） | 对地图的要求 |
|---|---|
| 探索者之间没有声音雷达或定位箭头（V1.2 2.10） | 不画任何人：队友、箱女、箱人都不画。“你在这里”只标自己 |
| 服务器只给每个角色下发它该知道的内容（V1.2 第 4 节） | 地图只按房子的固定布局画。容器的颜色只来自这名玩家自己知道的事（自己开过的、自己看见的，2026-11-26 起）；里面有没有东西、有没有藏人、别人在自己没看见时开过没有，图上都看不出来。秘密出口不画，4 块候选地毯也不画。地图不需要服务器另发数据 |
| 不得自行增加机制（V1.2 第 0 节） | 地图只能看：不能做记号，不能共享，也不能在图上交互 |
| 箱女的 3D 地图（V1.3 模块 T） | 箱女那边看到的内容和操作都不变 |

对照下来，下面的方案和已确认规则没有冲突。

## 3. 方案

### 3.1 规则【已定】

- 地图是每名探索者界面自带的，不是物品：不占背包格，不能丢，也捡不到别人的。
- 按 `Tab`【占位键位】打开或关闭，和箱女的地图是同一个键。
- 打开时照常能走能跑。不出声，不给箱女能量，没有别的代价。
- 不影响手电：打开地图前手电开着，关上地图后它还开着。

### 3.2 图上画什么【已定】

| 画什么 | 说明 |
|---|---|
| 房子本身 | 每个房间的轮廓和名字，名字和箱女地图用同一套（`HouseGraph.rooms[].label`）；走得过去的门洞、两部楼梯、土蔵。窗和朝院子的玻璃拉门画成墙，现在的模型已经是这样 |
| 院子和出口【建议】 | 围墙和三个出口：玄関大门、台所后门、院子的大门（冠木門） |
| 容器 | 位置 + 颜色（2026-11-26 设计者定）：自己没开过的是黄色，自己开过的是绿色，视野里看到队友开过的也变绿。什么算“开过”、“视野里看到”具体怎么判定，见 `Docs/HakoOnna_DevPlan_V1.4.md` 3.7 节（【建议】，设计者还没点头） |
| 保险箱、仏壇 | 居間北墙的保险箱，仏間东墙的仏壇。仏壇只标“仏壇”两个字，不写“超度地点”，因为超度怎么做还是【待定】（V1.3 待定第 8 项） |
| 你在这里 | 高亮自己所在的房间；走到别的房间时跟着换。人在院子里时不高亮 |

不画的：队友、箱女、箱人、物品、容器里有什么或有没有人、秘密出口。

### 3.3 画面和操作【建议】

- 用箱女的那套 3D 地图模型（`HouseMapProxy`），全屏显示，和箱女的地图一样。
- 打开时只显示自己所在的那层，镜头对准自己的房间，镜头朝向和自己面对的方向一致，所以屏幕上方就是自己的正前方。
- 土蔵留在真实位置，不像箱女地图那样往外推开，这样院子里的路才看得对。
- 后院的两条连接线（風呂 ↔ 土蔵、台所 ↔ 土蔵）不画。它们的意思是“箱女一次转移够得着”，不是能走的路，画出来会误导探索者。楼梯的连接线照画。
- 操作和箱女一样：右键拖动旋转，滚轮缩放，`Z` / `X` / `C` 只看一楼 / 只看二楼 / 看全部。
- 打开时 `WASD` 和 `Shift` 照常移动；鼠标不转视角；`E`、`F`、`G` 和滚轮切换物品都不起作用（数字键换物品、`T` 开关手电照常）。`Tab` 或 `Esc` 关闭。
- 正在搜索容器或输入保险箱密码时，按 `Tab` 没有反应。
- 被抓、被拉进容器、死亡转化、黑屏时，地图自动关闭。
- 开着地图走到别的房间，镜头跟过去。
- 蹲下：V1.4 定了按住左 `Ctrl` 蹲下（3.9 节和第 7 节第 3 条；键位【占位】），和地图的 `C` 不冲突。地图开着时也能蹲着走（V1.4 3.9，【建议】）。

### 3.4 美术交付（Claude）——2026-11-26 已交付

在 `HouseMapProxy` 上加了下面这些东西。每次重新生成房子时，地图模型会一起重做：

| 东西 | 说明 |
|---|---|
| 房间高亮 | 每个有地板的房间一块红色高亮地板（22 块；二楼两个楼梯井没有地板，`roomHighlights` 里是 null），默认关着。`Highlight(room)`：只亮这一间；传 `-1` 全部关掉 |
| 探索者专用标记 | 院子地面、围墙（大门处留口）、三道竹篱笆、三个出口（白色门槛 + 门外尖朝外的白箭头：玄関口、勝手口、表門）、金庫（青）、仏壇（紫）。出口、金庫、仏壇各有一个标名字用的挂点（`landmarks` / `landmarkLabels`）。默认关着，只在探索者视图里显示 |
| 探索者视图开关 | `SetExplorerView(on)`。打开时：显示探索者专用标记，隐藏后院连接线，所有容器刷成黄色（`HouseMapProxy.ExplorerUnopened`）；之后由程序把开过的刷成绿色（`HouseMapProxy.ExplorerOpened`）。关闭时和箱女以前看到的完全一样 |
| 接入步骤 | 已写进 `Assets/_Art/README_美术接入说明.md` 的“探索者地图”一节，可以直接照抄 |

- 绿色比黄色暗一截：分不清红绿的玩家靠亮度也能分开，开过的也不那么抢眼。
- 审图截图：`Docs/screenshots/detail/map_explorer_*_labeled.png`（5 张）和 `map_ghost_all_labeled.png`（确认箱女地图没变）。

### 3.5 程序要做的事（概要；能直接照抄的步骤随美术交付一起给）

- 探索者按 `Tab`：建一台地图相机（照抄箱女的设置，关掉后期），然后依次调用 `Map.SetExplorerView(true)`、`Map.Show(true)`、`Map.Explode(mapFloorGap, 0)`，把自己记录里开过的容器刷绿，再筛选到自己所在的楼层。
- 地图打开期间，每帧调用 `Map.Highlight(Graph.RoomAt(自己的位置))`。
- 每名探索者在本地记一份“开过的容器”，规则见 V1.4 3.7 节（【建议】）。
- 房间名和标记名用箱女地图的 `OnGUI` 写法，标在挂点上。
- 现在光标一解锁，`NetworkPlayer.Update` 就不读移动键了。地图打开时要改成照常读 `WASD` 和 `Shift`，只是不转视角。
- 箱女打开地图时调用 `Map.SetExplorerView(false)`，其余不变。
- 不新增同步变量、RPC 或声音键。地图的一切都只在本地。
- 镜头距离、楼层错开高度沿用 `mapOrbitDistance`、`mapFloorGap`。
- 验收：
  1. 探索者按 `Tab` 打开，`Tab` 或 `Esc` 关闭；搜索容器或输密码时按 `Tab` 没反应。
  2. 打开后显示自己所在的楼层，自己的房间是亮的；开着地图走到隔壁，高亮跟着换。
  3. 开着地图能走能跑；`E`、`F`、`G` 和滚轮不起作用。
  4. 容器：没开过是黄色，开过是绿色。箱女藏在里面、里面有什么、别人在自己没看见时开过的，都看不出来。
  5. 图上没有任何人。
  6. 后院连接线不显示，土蔵在真实位置。
  7. 没有新增网络数据。
  8. 箱女的地图和以前完全一样。

### 3.6 顺序

1. 美术改 `HouseMapProxy` 并重新生成场景，在 README 里写好接入步骤。——2026-11-26 已完成。
2. 程序按 README 接入。在美术交付之前，程序也可以先用现有模型把开关、相机和移动做出来，只是还没有高亮和标记。

## 4. 第一轮的决定（2026-11-23）

| # | 问题 | 设计者的决定 | 我当时的建议 |
|---|---|---|---|
| 1 | 地图做成哪种 | **按键打开的 HUD 地图**，界面自带 | 开局自带的物品 |
| 2 | 除了房子本身还画什么 | **容器位置、保险箱和仏壇、你在这里**，都画 | 都不画 |

2026-11-26 设计者改了玩法（同时还有：一部分容器上锁要找钥匙、背包 6 格、蹲下）。和地图有关的只有一条：**容器在地图上分颜色，自己没开过的黄色，自己开过的绿色，视野里看到队友开过的也变绿**。原来 3.2 和第 2 节里“所有容器永远是同一种颜色”的写法作废。那版玩法文档是 `Docs/HakoOnna_DevPlan_V1.4.md`：“开过”“看到”怎么判定写在它的 3.7 节，是【建议】，设计者还没点头。
